# bcgen-lang v0.4.1 — Initializers of a nested module

**A patch release.** A computed class constant or static property, an enum
case, and a computed constant or global declared inside a nested module (a
lowered `namespace`) read as `null` from the module's own body. No API change;
no behavior change for a unit without a nested module.

## The bug

LexerSketch's Mox demo showed it:

```php
<?php
namespace A;
class S { const C = [1]; }
echo count(S::C);        // 0.4.0: a type error; the same code without `namespace A;` printed 1
```

Literal initializers (`const X = 1;`) worked in both cases, and an `enum` in a
namespace broke because enum cases are computed constants.

## The cause

The start function (`<start>`) walks the unit's items in pre-order and does
the work of each: a class's constants and static properties, a global's
initializer, a nested module's body. A nested module is visited before the
declarations inside it, so its body ran first and read constants and statics
the start function had not computed yet. A literal initializer is an LSB
constant initializer and needs no code, which is why only computed values
were affected. At the root there is no such order problem: the root body runs
last.

## The fix

`Analysis::new` (`src/analysis.rs`) now orders the start function's work as a
stable partition: every initializer (globals, constants, classes, functions
with once-evaluated defaults) in canonical order, then the nested module
bodies in canonical order. It is linear, changes no public item, and leaves
the bytes of a unit without a nested module unchanged.

Two consequences worth knowing: a nested module's body also sees the
initializers of modules declared after it (PHP's namespaces share one global
scope), and bodies still run in source order among themselves.

## Tests

`tests/nested_modules.rs` builds the HIR as lower-lang emits a namespace (a
`Module` item holding the declarations, the statements as its body), resolves
it with resolve-lang 0.4's PHP policy, compiles it, and runs it on bvm-lang
2.0.0-alpha.4, in `BodyMode::Start` and `BodyMode::Entry`. Four of the five
programs failed on 0.4.0.

## Upgrading

`bcgen-lang = "0.4"` picks it up. Nothing else changes.
