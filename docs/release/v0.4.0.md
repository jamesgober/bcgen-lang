# bcgen-lang v0.4.0 — Classes

**Mox's objects.** v0.4.0 compiles HIR's classes, interfaces, and mixins (PHP
traits) to LSB structs with PHP 8's semantics: inheritance, constructors,
properties, instance and static methods, `self::`/`parent::`/`static::`,
static properties, constants, `new`/`instanceof`/`clone`, visibility,
exceptions as objects, and destructors. Classes were planned for 0.5; they
moved here because the LexerSketch Demo runs Mox, and Mox programs are full
of them. The release also closes four items from 0.3: PHP's ignored extra
arguments, Mox's `(int)` of an out-of-range float, string offsets through a
named intrinsic, and resolve-lang back in the end-to-end tests.

## What is bcgen-lang?

The bridge from a forged language's meaning to code the VM runs. It owns the
HIR to LSB translation: register allocation over LSB's register windows,
closure conversion, generators, pattern compilation, exception and `finally`
lowering by LSB's canonical scheme, classes, and debug information mapping
every instruction back to its HIR origin. It does not parse, resolve,
type-check, or execute. It is an LXRT-tier crate depending on hir-lang,
bytecode-lang, and intern-lang.

## What's new in 0.4.0

### Classes

```rust
use bcgen_lang::{BodyMode, Compiler, Intrinsics, Options};
use bvm_lang::{Host, Program, Value, Vm};
use hir_lang::{
    Binder, BinderKind, Builder, ClassDef, Def, Effects, Expr, FieldDef, FnDef, Ident, Item,
    ItemKind, List, Member, Name, Ns, OpKind, Param, ParamKind, Path, Res, Segment, Span, Vis,
};
use intern_lang::{Interner, Symbol};

// class Counter { public $n = 0; function inc() { return $this->n = $this->n + 1; } }
// $c = new Counter; $c->inc(); $c->inc()
let mut names = Interner::new();
let mut b = Builder::new();
let this = b.binder(Binder::new(Name::new(names.intern("this")), BinderKind::Param));
let pat = b.bind(this);
let recv = b.param(Param { kind: ParamKind::Receiver, ..Param::new(pat) });
let n = names.intern("n");
let field = |b: &mut Builder| {
    let t = b.use_binder(this);
    b.expr(Expr::Field { base: t, member: Member::Named(n), span: Span::empty(0) })
};
let (target, current) = (field(&mut b), field(&mut b));
let one = b.int(1);
let value = b.op(OpKind::Add, &[current, one]);
let body = b.expr(Expr::Assign { target, op: None, value });
let params = b.list(&[recv]);
let def = FnDef { params, body: Some(body), effects: Effects::NONE, ..FnDef::default() };
let inc_name = Name::new(names.intern("inc"));
let inc = b.item(Item::new(Some(inc_name), ItemKind::Fn(def)).with_vis(Vis::Public));
let zero = b.int(0);
let name = Some(Ident::new(n, Span::empty(0)));
let prop = b.field(FieldDef { name, vis: Vis::Public, ty: None, default: Some(zero) });
let (fields, items) = (b.list(&[prop]), b.list(&[inc]));
let class = ItemKind::Class(ClassDef { fields, items, ..ClassDef::default() });
let counter_name = Name::new(names.intern("Counter"));
let counter = b.item(Item::new(Some(counter_name), class).with_vis(Vis::Public));

let path = |b: &mut Builder, name: Symbol, res: Res| {
    let seg = Segment::new(Name::new(name), b.origin());
    let segs = b.list(&[seg]);
    let p = b.path(Path { res, ..Path::new(segs, Ns::Value) });
    b.expr(Expr::Path(p))
};
// `new Counter`, as the Mox sketch's `new_object` template writes it.
let new_sym = names.intern("mox.new");
let new_fn = path(&mut b, new_sym, Res::Extern(new_sym));
let class_res = Res::Def(b.def(Def::Item(counter)));
let class_ref = path(&mut b, counter_name.sym, class_res);
let object = b.call(new_fn, &[class_ref]);
let c = b.binder(Binder::new(Name::new(names.intern("c")), BinderKind::Local));
let pc = b.bind(c);
let let_c = b.let_stmt(pc, Some(object));
let method = Ident::new(inc_name.sym, Span::empty(0));
let call = |b: &mut Builder| {
    let receiver = b.use_binder(c);
    b.expr(Expr::MethodCall { receiver, method, generic_args: List::EMPTY, args: List::EMPTY })
};
let first = call(&mut b);
let first = b.expr_stmt(first);
let second = call(&mut b);
let body = b.block(&[let_c, first], Some(second));
let items = b.list(&[counter]);
let module = ItemKind::Module { items, body: Some(body), effects: Effects::THROWS };
let root = b.item(Item::new(None, module));
let hir = b.finish(root)?;

let opts = Options::new().with_body(BodyMode::Entry).with_intrinsics(Intrinsics::mox());
let out = Compiler::new(opts).compile(&hir, &names)?;
let entry = out.entry();
// The Mox runtime's host functions (only the slow paths reach them).
let mut host = Host::new();
for (_, def) in Intrinsics::mox().iter() {
    if let Some((module, func)) = def.lowering().host() {
        let _ = host.register(module, func, |_, _| Ok(Value::Nil));
    }
}
let program = Program::load(out.into_module(), &host)?;
assert_eq!(Vm::new(&program).run(entry, &[])?, Value::Int(2));
# Ok::<(), Box<dyn std::error::Error>>(())
```

- **One LSB struct per class and interface.** Single inheritance up to
  bvm-lang's 256 levels; the instance properties are the struct's fields, the
  parent's first (a private property is a slot per declaring class, so a
  parent's private `$x` and a child's `$x` are two properties, as in PHP).
- **Methods** take the receiver in register 0: the instance, or for a static
  method the class's token. `self::` and `parent::` are direct calls
  forwarding the receiver; `static::` looks members up on the receiver, so
  late static binding needs no hidden class argument.
- **Static properties and constants** are module globals made by the start
  function in the class's scope; subclasses share an inherited static
  property, as PHP does.
- **Interfaces** are marker methods (`instanceof` and `catch` test them) and
  carry their constants.
- **Mixins** are flattened into each using class by PHP's own algorithm
  (`zend_traits_copy_functions`): aliases, `insteadof`, visibility changes,
  and the mixin's properties, statics, and constants.
- **`new`, `instanceof`, `clone`** are class operations of the intrinsic table
  (`ClassOp`, `Intrinsics::with_class`): inline for the unit's classes
  (constructors, `__clone`, class values known only at run time through a
  name registry), the host function for anything else.
- **Visibility** is checked where PHP checks it: at compile time through a
  static path, at run time through an object, with PHP's messages raised as
  `TypeError`.
- **Exceptions are objects**: `catch` by class, interface, union, or
  intersection; non-objects still throw and catch as before.
- **Destructors**: `Compiled::destructor()` is the name to pass to bvm-lang's
  `Vm::set_destructor`; with `Options::with_reference_counting`, objects die
  where PHP frees them under bvm-lang's reference-counting profile.

`docs/API.md` has the full model and a table of PHP's class semantics: what
0.4 compiles, what it checks at run time, and what it refuses and why.

### Items closed from 0.3

- **`ignore_extra`** (ISSUES P34): `Options::with_ignore_extra(true)` drops
  extra arguments to user functions, as PHP does.
- **Mox `(int)` of a float** (ISSUES P41): a finite float outside the `i64`
  range wraps modulo 2^64 like PHP 8's `zend_dval_to_lval`; NaN and
  infinities give 0 (0.3 saturated).
- **String offsets** (ISSUES P38): `Options::with_string_offsets("mox.str_offset")`
  sends `$s[i]` to a table entry (an inline fast path for an in-range offset)
  instead of LSB's byte read; `docs/API.md` says how LexerSketch uses it.
- **resolve-lang** (ISSUES P35): the end-to-end and class tests resolve their
  programs with resolve-lang 0.4's PHP policy.

### How it is checked

- **`tests/classes.rs`**: 15 programs end to end (resolved by resolve-lang
  0.4, compiled, run on bvm-lang 2.0.0-alpha.4), each against PHP's output:
  inheritance and overriding, interfaces, statics and constants, late static
  binding, mixins, exceptions by class and interface, visibility, members by
  run-time name, and destructor order under reference counting.
- **`tests/class_model.rs`**: random hierarchies of up to 12 classes; every
  method call and property read, from every scope, against a model
  transcribed from PHP 8's `zend_std_get_method` and
  `zend_get_property_offset`. 5,000 hierarchies agreed before release.
- **`tests/mixins.rs`**: random graphs of mixins and rules PHP accepts; every
  flattened member against a model of PHP's trait copying. 5,000 graphs
  agreed before release.
- **`tests/hostile_classes.rs`**: random class graphs (cycles, deep chains,
  huge member counts, wrong kinds, malformed paths) compiled and run under
  budgets in both memory profiles, never a panic: 50,000 before release.
- **`tests/limits.rs`**: a chain of 256 loads, 257 is `ClassProblem::TooDeep`;
  huge classes and deep chains hit the instruction budget, not quadratic
  time.
- **The differential oracle** also runs every program compiled with
  `Options::with_reference_counting` (dead registers cleared): no result may
  change. 1,020,000 programs agreed under all three profiles before release.
- **`tests/intrinsics.rs`**: P41 vectors and 4,000 random float bit patterns
  against a model of `zend_dval_to_lval`.

## Breaking changes

Classes compile (`Unsupported::Class` now means only a receiver parameter
outside a class member); `Intrinsics::mox()`'s `mox.instanceof` and
`mox.clone` are class operations rather than host functions, and it gains
`mox.new` and `mox.str_offset`; Mox `(int)` wraps out-of-range floats instead
of saturating; the execution dev-dependency is bvm-lang `=2.0.0-alpha.4`. New
error variants are additions to `#[non_exhaustive]` enums.

## For the HIR, LSB, and tool owners

1. **lower-lang**: emit a `Receiver` parameter first in every instance method
   (`implicit_receiver`). Without it a Mox method lowered by lower-lang 0.4
   has no `$this`, so instance methods cannot run end to end through it.
2. **resolve-lang**: accept a class name in value position. The Mox sketch's
   `new_object` template writes `mox.new(Class, ...)`, which resolve-lang 0.4
   rejects ("expected a value, found class"); it also leaves an interface
   constant reached through an implementing class unresolved, and its trait
   member tables differ from PHP on some visibility rules.
3. **HIR**: a promoted-property marker on `Param` (constructor promotion), a
   `readonly` flag on `FieldDef`, a bare `self`/`static` path, and a way to
   name an interface in value position.
4. **LSB**: a destructor flag (ISSUES P44; the host uses
   `Vm::set_destructor` until then), `get_prop` by a run-time name, and
   `dsep`/`dref` through an object's property by a run-time name.
