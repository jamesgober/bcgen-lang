# bcgen-lang v0.3.0 — HIR 0.4, LSB Format 2, and the Mox Intrinsics

**The Demo's critical path.** v0.3.0 moves the compiler to HIR spec v3
(hir-lang 0.4) and LSB format 2 (bytecode-lang 0.3, which bvm-lang
2.0.0-alpha.3 runs), and compiles the named intrinsics Mox needs through an
intrinsic table. Those were the three things blocking the LexerSketch Demo
chain (lang-forge → lower-lang → resolve-lang → typeck-lang → bcgen-lang →
bvm-lang): typeck-lang 0.3 and bcgen-lang 0.2 were on different hir-lang
versions, the VM no longer read the bytecode bcgen-lang 0.2 emitted, and the
Mox intrinsics did not compile.

## What is bcgen-lang?

The bridge from a forged language's meaning to code the VM runs. It owns the
HIR to LSB translation: register allocation over LSB's register windows,
closure conversion, generators, pattern compilation, exception and `finally`
lowering by LSB's canonical scheme, and debug information mapping every
instruction back to its HIR origin. It does not parse, resolve, type-check,
or execute. It is an LXRT-tier crate depending on hir-lang, bytecode-lang,
and intern-lang.

## What's new in 0.3.0

### The intrinsic table (decision D27)

```rust
use bcgen_lang::{BodyMode, Compiler, Intrinsics, Options};
use bvm_lang::{Host, Program, Value, Vm};
use hir_lang::{Builder, Effects, Expr, Intrinsic, Item, ItemKind, List};
use intern_lang::Interner;

// 2 ** 10: two ints, so `mox.pow` runs inline as `dpow` (promote).
let mut names = Interner::new();
let mut b = Builder::new();
let (x, y) = (b.int(2), b.int(10));
let args = b.list(&[x, y]);
let sym = names.intern("mox.pow");
let pow = b.expr(Expr::Intrinsic { kind: Intrinsic::Named(sym), generic_args: List::EMPTY, args });
let module = ItemKind::Module { items: List::EMPTY, body: Some(pow), effects: Effects::NONE };
let root = b.item(Item::new(None, module));
let hir = b.finish(root)?;

let opts = Options::new().with_body(BodyMode::Entry).with_intrinsics(Intrinsics::mox());
let out = Compiler::new(opts).compile(&hir, &names)?;
let mut host = Host::new();
host.register("mox", "pow", |_, _| Ok(Value::Nil)); // the runtime's slow path
let program = Program::load(out.into_module(), &host)?;
assert_eq!(Vm::new(&program).run_export("<entry>", &[])?, Value::Int(1024));
# Ok::<(), Box<dyn std::error::Error>>(())
```

Each named intrinsic is an LSB sequence, a host function the embedder
provides, or a **guarded fast path**: the operands go straight into the host
call's window, their kinds are tested, and the inline LSB sequence runs where
LSB's result is exactly the language's (two ints for `%`, two strings for
`.`, the same scalar kind for `==`, ...); everything else calls the host.
`Intrinsics::mox()` maps all 26 intrinsics of the Mox sketch, and
`docs/API.md` states, for each, the fast domain and the PHP 8 semantics
LexerSketch's runtime must implement in the host function. An unknown name or
a wrong operand count is a precise compile error.

### HIR v3

- **Generators**: functions and closures with `YIELD` make coroutines
  (`coro_new`); keyed `yield` (`yield_kv`), automatic keys, `yield from` by
  HIR §8.7's delegation loop (keys preserved, sent values and thrown errors
  forwarded, the inner return value as the result). `await`; `spawn` through
  the module's scheduler hook; `ASYNC` functions run on LSB's stackful model.
- **`let_place`**: a place's operands evaluated once into registers, and
  every read, write, reference, and further step through the alias, so
  `$a[f()] .= "x"` calls `f` once. Assignments evaluate to the value written.
- **OPS v2**: `pow` (`dpow`, with `NegativeExponent`), `bit_not` (and `not`
  logical only), `shift = saturate`, `abs` through `dabs`.
- **`NoMatch`**: a `match` with no matching arm raises E0200 with the
  scrutinee as payload.
- **Unions and intersections** in type tests and checked casts.

### LSB format 2

- **Parameter lists**: every function item and closure carries its LSB
  parameter list; dynamic calls are `dcall`/`dcall_shape`, bound by the VM
  (`ArgumentError` at the call). The 0.2 argument packets are gone.
- **References**: `$x = &$a[k]` (`dref_index`), `$a[k] = &$x`
  (`dbind_index`), element place arguments to by-reference parameters, and
  run-time by-reference decisions for dynamic calls (`dparam_ref`).
- **Separation that copies only what is shared** (`dsep_index`/`dsep_prop`):
  100k nested writes `g[i % 64][] = i` take 23 to 29 ms, from 415 ms.
- `raise` for `NoMatch` and type errors; `dpow`, `dabs`.

### How it is checked

- **The differential oracle**, extended: the reference interpreter and the
  random program generator gain `let_place`, `pow`, `bit_not`, saturating
  shifts, union type tests, LSB's binding rules, and `NoMatch`. 1,320,000
  programs agreed under both array profiles before release.
- **`tests/features_0_3.rs`**: 26 programs for the forms the generator does
  not reach (generators with sends, throws, and delegation; `await`/`spawn` on
  bvm-lang's scheduler; references into elements; dynamic calls with named
  arguments and spreads), each against PHP's result.
- **`tests/intrinsics.rs`**: every Mox mapping against a test host that
  implements PHP 8's semantics, over every pair of a 37-value scalar pool:
  each fast path gives exactly the host's result on its documented domain
  and calls the host exactly for the operands outside it.
- **`tests/binding.rs`**: a direct call's compile-time arrangement and the
  VM's binding of the same call through the function value agree on random
  parameter and argument lists.
- **`tests/hostile.rs`**: random HIR mixing every form anywhere, repaired by
  `finish_lenient`, never panics (200,000 programs before release); 20,000
  nested `let_place`s and union types compile on a 512 KiB stack.

## Breaking changes

See the CHANGELOG's migration table. In short: hir-lang 0.4 and
bytecode-lang 0.3 types in the API; the calling convention is LSB's (no
packets); binding errors are `ArgumentError` at the call; an unmatched
`match` raises `NoMatch`; HIR `not` is logical; named intrinsics need a table
entry (`Options::new()` has the core ones); `CompileError::IntrinsicArity`'s
fields, two new `CompileError` variants, and `Unsupported::Coroutine`
removed.

## Known deviations

Recorded in `dev/ROADMAP.md`: after `yield from` the outer generator's
automatic key continues after the inner one's largest integer key (PHP keeps
its own); delegating to an already advanced generator resumes it (PHP
re-yields its current value); generator defaults are evaluated at the first
resume; extra arguments to a function raise `ArgumentError` (PHP ignores
them; a language switch is planned for 0.5); reference slots are not unbound
when their last other holder dies (LSB §5.17's divergence; `dunref_*` is not
emitted yet).

## For the LSB and HIR spec owners

1. **Yield under a key without moving the automatic key (LSB §5.13 rule 10).**
   The spec's `yield from` loop re-yields with `yield_kv`, which moves the
   delegating generator's counter; PHP's counter is per generator and not
   moved by delegation. A `yield_kv` modifier (or a `yield_delegated`) would
   make the loop exact.
2. **A coroutine's current value (LSB §5.13).** `yield from` on an already
   advanced PHP generator first re-yields its current value; LSB has
   `coro_key` but no `coro_current_value`.
3. **Extra arguments (HIR §10).** PHP ignores extra arguments to user
   functions (LSB's `ignore_extra`); HIR has no way to say a language wants
   that, so it is an `Options` switch to come (or a HIR flag on `FnDef`).
4. **Host functions as values.** `load_import` makes them first class, but
   the compiler only knows a host symbol's name, not its parameter list; a
   host-signature table (like the intrinsic table) would let `Res::Extern`
   values and named arguments to host functions compile.
